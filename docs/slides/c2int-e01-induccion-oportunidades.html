Dos formas de alimentar un tablero

A mano

  • Alguien descarga un archivo
  • Copia y pega en una hoja
  • Corrige a ojo lo que ve mal
  • Nadie sabe qué cambió ni cuándo

Reproducible

  • Un programa pide los datos a su fuente
  • Guarda el dato original intacto
  • Aplica reglas escritas y probadas
  • Se ejecuta solo y deja registro

Primer eslabón

¿Qué es una API?

Es una forma ordenada de pedirle datos a otro programa, como pedir en un restaurante.

Una petición, por dentro

Pides con una dirección y un verbo

GET https://api.ejemplo.com/v1/ventas?fecha=2026-11-09&pagina=1 Authorization: Bearer <tu-llave>
VerboGET pide datos; otros verbos, como POST, los envían
EndpointLa dirección de lo que pides: aquí, las ventas
ParámetrosLo que filtra: la fecha y la página
LlaveQuién eres: la API sabe quién pregunta

La dirección es de ejemplo.

La respuesta

Llega en JSON: datos dentro de datos

{ "pagina": 1, "datos": [ { "id": 101, "cantidad": 2, "producto": { "nombre": "Camiseta", "precio": 45000 } } ] }
  • Los datos vienen en niveles: el producto va dentro de la venta
  • Una tabla necesita filas y columnas planas
  • En pandas, json_normalize aplana los niveles en columnas
La API siempre responde con un código

Tres códigos que vas a ver todo el tiempo

200

Todo bien. La respuesta llegó completa: sigue.

429

Demasiadas solicitudes. Espera un momento y reintenta con pausa.

500

Falló el servidor. Reintenta unas veces y, si sigue, registra el error.

Las APIs no entregan todo de una vez

Páginas y límites de solicitudes

La llave es tuya

Las llaves nunca viajan dentro del código

Nuncallave = «abc123» escrita en el script y subida a GitHub
SiempreLa llave va en una variable de entorno o en un archivo .env que no se sube al repositorio.

Si una llave se sube por error, se revoca y se crea otra. No basta con borrarla del repositorio.

Una palabra que usaremos todo el curso

¿Qué hace reproducible a un flujo?

  • Otra persona lo ejecuta desde cero y obtiene lo mismoSin depender de tu computador ni de tu memoria
  • El dato original se conserva y las reglas están escritasSe puede ver qué cambió y por qué
  • Las llaves y rutas no están dentro del códigoSe pueden cambiar sin tocar el programa
  • Si algo falla, queda un registroNo se publica un resultado dudoso en silencio
Pregunta clave del encuentro

¿Qué parte de los datos necesita actualizarse?

Cambia poco

Catálogo de productos, lista de sedes, nombres de áreas.

Se carga una vez y se revisa de vez en cuando.

Cambia siempre

Ventas, solicitudes, visitas, pagos.

Es lo que justifica automatizar la extracción.

Tres lugares donde buscar datos para practicar

APIs públicas

Servicios abiertos de gobiernos, clima, transporte o bibliotecas. Verifica sus límites de uso.

Datos abiertos

Portales de ciudad y de país: archivos o API, con licencia de uso.

Datos sintéticos

Los generamos con una API de prueba o un mock. Sin datos reales de nadie.

Antes de elegir, mira los riesgos

Cuatro preguntas para descubrirlos

  • ¿Puedo conseguir los datos hoy, sin pedir un permiso que tarde semanas?
  • ¿Contienen información de personas? Si sí, busco una alternativa pública o sintética.
  • ¿Se actualizan con la frecuencia que la decisión necesita?
  • ¿Es lo bastante pequeño para terminarlo en cinco semanas?
