Con prestamos_abril, no autodetectes

La trampa del esquema

# Esquema → Editar como texto prestamo_id:INTEGER, socio_id:INTEGER, libro_id:INTEGER, fecha_prestamo:STRING, fecha_devolucion:STRING # Las fechas de abril llegan como 30/04/2026

Si BigQuery adivina «fecha», falla o la entiende mal. En abril, cargamos el texto tal cual y lo convertimos nosotros con SQL.

Tu primera consulta

Pregúntale a la tabla

SELECT libro_id, titulo, categoria FROM `biblioteca.libros` LIMIT 5;

Antes de ejecutar, mira arriba a la derecha: «Esta consulta procesará X». BigQuery cobra por lo que lee, no por lo que devuelve.

Una tabla nueva, a partir de otra

Guarda un resultado como tabla

CREATE OR REPLACE TABLE `biblioteca.prestamos_por_libro` AS SELECT l.titulo, COUNT(*) AS prestamos FROM `biblioteca.prestamos` AS p JOIN `biblioteca.libros` AS l USING (libro_id) GROUP BY l.titulo;

Es el paso que usará tu flujo para dejar datos listos: una consulta que se queda guardada como tabla.

Para el nivel 3 y el 4

Tres herramientas que necesitarás

1JOINPara unir préstamos con libros por libro_id.
2GROUP BY + HAVINGPara contar por grupo y quedarte con los repetidos.
3PARSE_DATEConvierte texto a fecha: PARSE_DATE('%d/%m/%Y', fecha_prestamo).

Escribe las columnas que necesitas, no «*», y mira los bytes antes de ejecutar.

Si la consulta no corre

Los errores más comunes

Not found: TableRevisa que tengas tu proyecto seleccionado y las comillas invertidas ` alrededor del nombre
Unrecognized nameUna columna mal escrita. Mira el esquema de la tabla
Ambiguous columnDos tablas tienen esa columna. Escríbela con el alias: p.libro_id
Could not cast literalLa fecha no tiene el formato que dijiste en PARSE_DATE
