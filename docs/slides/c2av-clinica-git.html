Clínica de Git · 30 minutos

Git, sin miedo

Lo justo para guardar, compartir y revisar trabajo en pareja

Empecemos por separar dos cosas

Git

La herramienta que guarda la historia de tus archivos, en tu computador.

GitHub

El sitio donde subes esa historia para compartirla, revisarla y trabajar en equipo.

La idea central

Cada commit es un punto en tu historia

Un buen mensaje cuenta qué cambió, no «arreglos varios».

Por dónde viaja un cambio

Tu carpeta, el área de preparación, el repo y GitHub

1Tu carpetaEditas el archivo
2git addEliges qué entra en el próximo commit
3git commitGuardas la versión en tu repositorio
4git pushLa subes a GitHub
Hagámoslo juntos · 8 minutos

Clonar, escribir, guardar, subir

# 1. trae el repositorio a tu computador git clone https://github.com/tu-usuario/tu-repo.git cd tu-repo # 2. crea oportunidades.md y escribe tu primera oportunidad git status git add oportunidades.md git commit -m "Agrega mi primera oportunidad" git push

Si algo falla, pregunta: casi siempre es una ruta o un permiso.

Para no tocar lo que ya funciona

Una rama es un camino paralelo

git switch -c mi-oportunidad # crea la rama y te pasa a ella
Cómo se pide una revisión

Un pull request es una conversación

1Empuja tu ramagit push -u origin mi-oportunidad
2Abre el PREn GitHub, con título y una descripción breve
3Tu pareja revisaComenta líneas concretas y pide cambios o aprueba
4RespondesAjustas, haces otro commit y el PR se actualiza solo

En este curso la revisión por pareja importa más que fusionar.

Revisar también se aprende

Cuatro hábitos de una buena revisión

  • Lee primero la descripciónEntiende qué quiso hacer la otra persona
  • Comenta sobre la línea concreta«Aquí no queda claro quién decide» sirve más que «mejorar»
  • Pregunta antes de corregirQuizá hay un motivo que no ves
  • Termina diciendo qué está bienAprobar con una razón, no con un sello
Lo que más asusta, y no es tan grave

Un conflicto es Git pidiéndote una decisión

<<<<<<< HEAD Decide cuánto personal asignar cada lunes. ======= Decide cuánto personal asignar cada semana. >>>>>>> mi-oportunidad
  • Abre el archivo y elige qué versión queda, o combínalas
  • Borra las tres líneas de marcas: «<<<», «===», «>>>»
  • Guarda, haz git add y un commit
Lo que casi todos hacemos

Cuatro tropiezos y su salida

TropiezoHice commit en la rama equivocada
SalidaPide ayuda antes de forzar nada: se corrige sin perder trabajo.
  • «Rejected»: alguien subió antes → git pull y luego push
  • Archivos de más en el commit → revisa con git status antes
  • Contraseña o llave en el repo → avísame de inmediato, hay que cambiarla
Para dejar en el escritorio

Hoja de comandos

git status # qué cambió git add archivo # prepara el cambio git commit -m "mensaje" # guarda la versión git push # sube a GitHub git pull # trae lo nuevo del equipo git switch -c rama # crea una rama y entra git log --oneline # historia resumida
